# 工位打卡 · Desk check-in

一个挂在 dsh-pet 桌宠上的工作日打卡与学习记录插件。

## 它做什么

1. **打卡**：记录你今天几点到工位。判断口径有两条，每次都一起说：
   - 固定基准线（默认 `09:00`，可改）；
   - 你最近 10 个工作日的平均到达时间。
   
   比基准/平均早，就夸一句；晚了，就说一句「坐下了先做最要紧的那件」。
2. **每日记录**：每天 21:30（可改）桌宠会提醒你写下今天学了什么；没记录就一直提醒到当天结束。记录会顺手补一次打卡。
3. **感想单独一栏**：`记` 存的是事实（看了什么、跑通了什么），`感想` 存的是判断和情绪（烦、爽、怀疑方向）。两者分开存——学习记录进统计，感想原样进公众号版周报。
4. **周报**：每周五 21:45（可改）自动汇总，写两个文件：
   - `week-YYYY-MM-DD.md`：统计表，自己复盘用；
   - `week-YYYY-MM-DD-article.md`：成文版，段落叙述、第一人称，可直接当公众号草稿。
5. **连续出勤**：连续来了多少个工作日、历史最长多少天、累计多少天。规则有几条是刻意这么定的：
   - 周末整段跳过，既不计数也不打断——周末本来就不来，算不上「断了」；
   - **今天没打卡之前不判它断**：早上九点还没打卡不代表连续记录结束了，断点只由已经过去的工作日产生；
   - 打卡文案里会带上「连续第 N 个工作日」；连续 ≥3 天时，周报的「下周」那节会改成「别把这个数断掉」，而不是泛泛地说加油。
6. **想学的池子**：想到什么丢进去，不排日期。做完了打勾，顺手往当天学习记录写一条；撤销打勾会把那条记录精确收回。详见下面「想学的池子」一节。
7. **持久记忆**：所有数据落盘在 `DSH_HOME/dsh-gongwei/state.json`，并且每天的最新状态会进入对话上下文——你直接问「我这周怎么样」我就知道，不需要你复述。
8. **桌宠也知道**：同一个摘要还会挂到 dsh-pet 的对话记忆槽（`petApi7340.memory`）上，所以你跟小鱼聊天时它也知道你今天几点到、学了什么、连续几天了。

## 成长手记

设置页的「今天」更名为「成长手记」，包含日记和每周回顾。日记按卡片、段落及常用 Markdown 阅读，支持展开与复制原文；每周回顾可切换统计/成文两版，预览不写盘，点击「生成并保存」才归档。出勤仍按工作日统计，周末写下的学习与感想不会从周报遗漏。

桌宠记录气泡采用换行编号；本周战绩展示出勤、学习、连续三行概览，并在同一动作里把本周两份周报落盘，气泡指向成长手记。换行样式使用 `tools/patch-pet-lines.mjs` 本地补丁，升级 dsh-pet 后需重跑并重载桌宠、刷新网页：

```bash
node tools/patch-pet-lines.mjs            # 打补丁（幂等）
node tools/patch-pet-lines.mjs --check    # 只看状态
node tools/patch-pet-lines.mjs --restore  # 用 .pre-lines.orig 还原
```

## 五种用法

| 入口 | 怎么做 |
| --- | --- |
| 桌宠右键 | 右键小鱼 → **对话**（已从「更多」挪到「碎碎念」前）/ 待办事项 / 打个卡 / 今天记录 / 记条感想 / **想学什么** / 本周战绩。点「打个卡」会用克隆音色念一句按当天情况变化的问候 |
| 斜杠命令 | `/gongwei 打卡`、`/gongwei 记 今天看完了 LoRA 那篇`、`/gongwei 感想 方向还没定下来`、`/gongwei 想学 把 RetNet 的 cache 搞明白`、`/gongwei 池子`、`/gongwei 完了 1`、`/gongwei 撤销 1`、`/gongwei 搬`、`/gongwei 状态`、`/gongwei 周报`、`/gongwei 公众号` |
| 设置页 | DSH 设置 → **想学的**：直接敲、直接勾、改正文、加备注、两步确认删除、「从待办搬过来」；DSH 设置 → **成长手记**：日记按段落与常用 Markdown 排版，可展开/复制原文；每周回顾内直接阅读统计与成文两种周报，支持生成归档 |
| 直接对话 | 「打个卡」「记一下：今天跑通了 xx」「感想：这周有点浮躁」「我想学 Chroma 的检索参数」「这个看完了」「池子里还剩什么」「这周我怎么样」「出个公众号版周报」 |
| 工具 | 对话里的模型会调 `gongwei` 工具，`action` 取 `checkin / log / think / status / week / config / plan_add / plan_list / plan_today / plan_done / plan_undo / plan_drop / plan_note / plan_import` |

五种入口写的是同一份数据。

命令的动词和正文之间，**冒号（全角 `：` 或半角 `:`）、逗号、顿号、空格都行**，前面带「我想学 / 帮我记 / 麻烦记一下」这类口头主语也会被自动去掉。所以下面这些写法等价：

```text
/gongwei 想学：把 RetNet 的 cache 搞明白
/gongwei 想学:把 RetNet 的 cache 搞明白
/gongwei 我想学 把 RetNet 的 cache 搞明白
/gongwei 添加 把 RetNet 的 cache 搞明白
```

每个动词都有一组别名：`/gongwei 池子` 也能写 `/gongwei 清单`，`/gongwei 完了 1` 也能写 `/gongwei 划掉 1`。**认不出来的动词会直接报错**，不会静默变成别的动作（早先的实现里，打错字会被当成一次打卡，把当天打卡时间也改掉——这个坑已经填了）。

**但它们能做的动作不一样**：桌宠右键菜单只有「回执」能力——点「今天记录」它会把今天记过的内容念给你听，点「本周战绩」它把本周概览念出来并顺手落盘两份周报，点「想学什么」它把池子里最上面三条念出来。真正写字要在对话里（`记一下：…` / `/gongwei 记 …`），或者在设置页的「想学的」面板里直接敲——因为桌宠的气泡没有输入框，插件也没有任何接口能往那个输入框里预填文字。

例外是「打个卡」：除了落盘打卡，还会用克隆音色（`clone/custom`）念一句**按当天情况变化**的问候。文案由 `checkinVoiceText(result, { hook, seed })` 生成，固定两行结构：

- **第一行是「到了」**：`arrivalLine(stamp, verdict, seed)` 按时段分档（比平常早 / 晚 / 差不多 / 没有历史）各准备 3 句，再用 `keySerial(dateKeyOf(now))` 按天轮换，同一天重复点不会换词。连续出勤 ≥2 天追加一句，逢 5 的倍数换成「连续第 N 个工作日，这条线还没断。」
- **第二行是「钩子」**：`checkinHook(now)` 按优先级挑一句能勾住人的话——
  1. **昨天自己写过的话**。把昨天最近的 2 条感想 + 2 条记录拆成小句，用 `bestIntent()` 打分：有「打算/准备/先把/要…」这类行动词 +3，动作动词开头 +2，**带引号 −4**（多半在复述别人的话，拎出来问很怪），「觉得/感觉/可能」−1，句长再 +0~2。挑中后摘掉「明天/今天」这类时间词，套进「昨天你提到「…」，今天要不要先动它？」。挑到明确打算用催促口吻，只是想法就换成「今天想从哪儿接？」，不硬说成「你昨天说要做」。
  2. **池子还欠的**：`池子里还欠 N 条，今天挑一条？「…」`。
  3. **本周进度**：`这周已经到 A/B 天。`
  4. 都没有就**只留第一行**——宁可短，也不凑字。
- 重复打卡仍是「今天已经打过卡啦，别贪心，去忙吧～」一行。
- 刻意不念 `checkinSentence` 那套「基准/平均」的报表话（念出来像汇报），那套留给对话和 `status`。

实现见 `sayWithVoice(text)`：往 `/broadcast` POST `{text, duration, speak:true}` + `?surface=desktop`——**surface 必须是 `desktop`/`web` 才会写 `voiceTo` 触发发声**，`any`/`both` 映射不到目标、不会出声；合成失败（CosyVoice2 需余额，失败返回 `ok:false`）会记日志并回退成普通气泡，保证话不丢。气泡与语音共用同一份文本（`/broadcast` 只有布尔 `speak`，没有单独的口播文案字段），所以钩子也控制在 24 字以内，念出来不啰嗦。只有打卡出声，其余菜单项仍只弹气泡。

## 想学的池子

数据在 `state.json` 顶层的 `plans` 数组，跟 `days` 平级。设计上跟「待办事项」刻意分开：

- **没有 `dueAt`**。它不是待办，是素材库。什么时候做由你决定，插件不排期、不催。
- **打勾即记录**。`finishPlan` 往当天 `entries` 写一条 `看完了想学的：<正文>`，还没打卡就补上；`planLogTs` 记住这条记录的 `ts`。
- **撤销按 ts 精确收回**。`reopenPlan` 用 `plan.planLogTs` 过滤 `entries`，绝不按文字匹配——同一句话你可能自己手记过一条，按文字删会误伤。
- **周报算得进去**。`weekStats` 多返回 `plansDone / plansOpen / plansAdded`；统计版多一行概览和 `## 想学的` 小节；成文版**不重复列**（划掉时已进当天记录）。
- **从旧待办一次性搬迁**。`importPetTodos()` 读 `$DSH_HOME/dsh-pet/todos.json`，去重后搬过来，已完成的保持 `done` 状态但**不写 `planLogTs`**（当初没生成记录，撤销时也就无从收回）。
- **和桌宠待办的日常同步**：池子是唯一真相源，桌宠「待办事项」是它的投影（带 `[想学]` 标记）。**桌宠里没设截止时间的原生待办会自动收进池子并补上标记**——按用户自己的口径「带截止=限期交作业，留在待办；不带截止=想学，进池子」。带 `dueAt` 的限期任务一个字不碰。不想要这个自动收编可设 `config.adoptUntimedTodos=false` 退回老行为。

```jsonc
{
  "id": "p3-mwlthkaj",          // p<seq>-<base36 时间>，seq 存在 meta.planSeq
  "text": "把 RetNet 的 cache 机制搞明白",
  "note": "先看第三章",          // 备注，≤500
  "source": "chat",             // chat / panel / pet-todo
  "done": false,
  "createdAt": 1794000000000,
  "doneAt": null,
  "doneDay": null,              // YYYY-MM-DD
  "planLogTs": null             // 自动写的那条学习记录的 ts
}
```

排序 `sortedPlans()`：未完成在前（`createdAt` 倒序，**新的在前**），已完成在后（`doneAt` 倒序）。所以 `plan_list` 里的「1」是最新丢进去那条，不是最早那条。

`findPlan(ref)` 的定位顺序：纯数字 = 上面的序号（1 起）→ 精确 id → 正文双向包含。命中多条时返回 `{ ambiguous: [...] }` 而不是 null，调用方必须判 `found.ambiguous`——这是刻意让它显式失败，而不是随便挑一条替用户做决定。

## 配置

改 `DSH_HOME/dsh-gongwei/state.json` 的 `config` 段，或者直接对我说，我调工具改：

```jsonc
{
  "reminderTime": "21:30",  // 每日记录提醒时间
  "baseline": "09:00",      // 打卡基准线
  "weeklyDay": 5,           // 周报日，1=周一 … 7=周日
  "weeklyTime": "21:45",    // 周报生成时间
  "petId": "",              // 留空自动发现
  "adoptUntimedTodos": true // 桌宠待办里没设截止时间的原生条目，自动收进「想学的」池子并补上 [想学] 标记；
                            // 带截止时间的是限期任务，留在待办当任务不动。设 false 退回老行为（原生待办一律不碰）
}
```

## 数据文件

```
DSH_HOME/dsh-gongwei/
  state.json                       # 全部打卡、记录、感想
  reports/week-YYYY-MM-DD.md       # 统计表周报
  reports/week-YYYY-MM-DD-article.md # 公众号成文版
```

`state.json` 里每天一条：

```jsonc
{
  "checkin": "09:12",             // 到达时刻
  "checkinTs": 1794970183258,     // 毫秒时间戳
  "entries":  [{ "at": "14:30", "ts": 0, "text": "跑通了 baseline" }],  // 学习记录
  "thoughts": [{ "at": "22:10", "ts": 0, "text": "方向还没定下来" }]    // 感想
}
```

纯 JSON，可以直接备份、手改、或拿去做别的分析。老版本的单字符串 `note` 字段会被自动当作第一条感想接过来，不会丢字。

数据目录默认跟着 `DSH_HOME`；想挪到别的盘，设环境变量 `GONGWEI_DATA_DIR`（例如 `E:\DSH\data\dsh-gongwei`），重启应用生效。

## 已知边界

- 只在工作日统计（周末的打卡会记录但不计入应到天数）。
- 连续天数按「有打卡的工作日」数，不区分来得早晚——来了就算，这是我们说好的口径。
- 「平均」用最近 10 个有打卡的工作日，样本不足时只报基准线。
- 桌宠睡着时气泡会被宿主拦掉，但打卡数据照常写入。
- 菜单项是进程内存态，DSH 重启后由插件自动重注册（内置 `unknown-owner` 兜底）。
- 周报错过时刻会补发：不看「现在到点了没」，而是看「最近一次该交的时刻」比已交记录新多少，最多回溯一周。首次安装不补发空周报。
- 成文版周报是**草稿**：它把当周的事实和感想组织成文章，但语气是你的、要不要发也是你的事，模型可以再按自己的声音改。
- 桌宠气泡的文本上限是插件自己定的 **120 字符**（宿主不限长）。这个数是量出来的：whisper 气泡宽 `fontSize × 10.989`、高约 `fontSize × 11.5`，本机字号 23 → 一行约 14 个汉字、最多 9 行。所有提醒文案都在这个长度内。
- 桌面宠物只能显示一段连续文字（换行会被折成空格），也**不支持 markdown、不能用链接**，点气泡只会把它戳破。
- 气泡里的摘要是模型压缩的结果，**原文一个字都不改**——它是周报和公众号的素材。
- 桌宠对话的记忆是**只读追加**：插件往 system 末尾加一段「工位记录」，不改人设、不改历史。小鱼说了什么仍然由它自己的模型决定。

## 内容太多怎么办：气泡放摘要，全文进设置页

「今天记录」「记条感想」原来是把最近两条原文拼起来塞进气泡，一条记录几百字时必然被截成半句话。现在分三层：

1. **气泡只放摘要**：`今天 3 条（559 字）：…｜…｜…  全文在设置页「今天」`。每条压成一句人话，放不下就写「另 N 条」——「另 3 条」有信息量，半句话没有。截断按句读切（先找 `。！？；`，再退到 `，、`），不会停在「了解了机器学…」这种地方。
2. **摘要由模型压**：走宿主的 `llm` 服务，用你当前对话选中的模型。要求它带编号输出（`3|短句`），插件按编号对回原文——它偶尔会把两条并成一条，对不上编号的那条单独退回启发式首句，不会整体错位。提示词里明确「只能用原文里出现过的信息，不要补充、不要推测」，防止它脑补原文没提过的计划。
3. **全文在设置页「今天」**：DSH 设置 → **今天**，有滚动、可复制、段落完整可读。

两个刻意的实现细节：

- **写入时就预热摘要**。点菜单才现算的话，模型要跑十几秒，人就对着空气等。所以每次 `记`/`感想` 落盘后，后台就悄悄算一次并存进缓存；DSH 启动时也会把当天已有内容预热一遍。点下去通常直接命中缓存，一次气泡就出来。
- **冷启动分两步弹**。万一预热还没跑完就点了，先弹启发式首句，模型好了再覆盖一次（内容没变则不弹，避免闪）。宁可先粗糙，也不让人干等。

摘要缓存以「类型 + 内容指纹」为键，同一批记录反复点菜单不会重复花 token；模型失败（超时、限流、没配模型）一律静默降级到启发式，只留一条 warn 日志，不能因为这个把菜单点崩。

## 已知边界（摘要相关）

- 摘要要花一次模型调用（约十几秒、几千 token 输入）。太短的内容（总共 ≤60 字）不调模型，直接取首句。
- 换了内容就会重新算一次；同一天的记录越多，摘要越长。

## 菜单为什么在第一层（本地补丁）

dsh-pet 没给第三方插件留「菜单位置」的口子：菜单树是客户端硬编码拼出来的，第三方注册的项一律只能落进「更多」。要让它出现在第一层，只能改 dsh-pet 的已安装产物——两处。补丁顺带把内置的「对话」从「更多」挪到第一层「碎碎念」前面：

| 端 | 文件 | 改完怎么生效 |
| --- | --- | --- |
| 桌面端 | `node_modules/dsh-pet/runtime/electron-helper/sprite/menu.js` | `POST /dsh-pet-7340/reload`，或右键菜单 →「更多」→「重载配置」 |
| 网页端 | `node_modules/dsh-pet/lib/client.js` | 刷新浏览器页面 |

打补丁的脚本在 `tools/patch-pet-menu.mjs`：

```bash
node tools/patch-pet-menu.mjs            # 打补丁（幂等，已打过就跳过）
node tools/patch-pet-menu.mjs --check    # 只看状态
node tools/patch-pet-menu.mjs --restore  # 用 .orig 还原成上游原样
```

**升级或重装 dsh-pet 会覆盖这两个文件，菜单会退回上游顺序**——那时候跑一次 `node tools/patch-pet-menu.mjs` 再重启桌面 Helper 就恢复了。脚本先检查标记 `const PINNED_OWNER = 'dsh-gongwei';`，已打过就跳过；打之前会把原文件备份成 `*.orig`（已存在不覆盖）。如果 dsh-pet 大改版导致锚点找不到，脚本会直接报错退出、不写文件。

## 原生待办事项：改名 / 改到期（本地补丁）

用户更习惯直接在 dsh-pet 自带的「待办事项」里加东西，但它原生只能加/勾/删。另一个补丁 `tools/patch-pet-todo.mjs` 给每条待办加了两个就地按钮：

| 按钮 | 行为 |
| --- | --- |
| ✎ 改名 | 点一下正文变输入框，回车/失焦保存、Esc 取消；空串或没改不提交（走 `PATCH /todos/:id {text}`） |
| ⏰ 改到期 | 点一下出 `<input type="datetime-local">`（初值取该条现有到期日），回车/失焦保存、Esc 取消；清空 = 无期限（走 `PATCH /todos/:id {dueAt}`） |

都是纯前端改动，用 dsh-pet **已有的** PATCH 路由，不碰 `todos.json` 的数据结构（备注/分类之类存不进去——`parseTodoRecord` 会剥掉未知字段，所以没做）。

| 端 | 文件 | 生效方式 |
| --- | --- | --- |
| 桌面端 | `node_modules/dsh-pet/runtime/electron-helper/shared-core.js` | `POST /dsh-pet-7340/reload` |
| 网页端 | `node_modules/dsh-pet/lib/client.js` | 刷新浏览器页面 |

## 待办面板：一次看到更多条（本地补丁）

原生面板把清单高度写死成「量一次行高 × 2」（`const LIST_ROWS = 2`），待办攒到十几条时一次只露两行、往下翻很别扭。`tools/patch-pet-todo-tall.mjs` 改四个地方，全在渲染层，不碰 `todos.json`：

| 改动 | 为什么 |
| --- | --- |
| `LIST_ROWS` 2 → 6，再按 `window.innerHeight` 夹一次，最少保 2 行 | 高窗口多看几条，矮窗口不会把面板顶出屏幕 |
| 没截止时间的条目不再显示「无期限」副标题 | 这行零信息量却占满一整行；去掉后大多数条目从两行变一行，同样高度能装的条目翻倍 |
| 清单加常驻细滚动条（`::-webkit-scrollbar` 6px） | 一眼看出「下面还有」，不再靠猜 |
| 正文里的 `[想学] ` 前缀渲染成小徽章 | 那是插件写进文本的内部标记，当正文显示既丑又占宽度 |

面板整体高度由 `TODO_PANEL_METRICS` 里「清单+提示」与日历的**较大值**决定，清单涨到 6 行仍在日历那份预算之内，所以 `todoPanelTopMarginPx`（桌宠窗口上边距）不用跟着改。

```bash
node tools/patch-pet-todo-tall.mjs            # 打补丁（幂等）
node tools/patch-pet-todo-tall.mjs --check    # 只看状态
node tools/patch-pet-todo-tall.mjs --restore  # 用 .pre-todotall.orig 还原
```

标记 `/* dsh-pet-todo-tall v1 */`、备份后缀 `.pre-todotall.orig`。锚点共 5 处（`LIST_ROWS`、`capListHeight`、`renderItem`、滚动条 CSS、徽章 CSS），每处必须恰好命中一次，否则报错退出、不写文件——dsh-pet 升级改了结构时会在这里拦住。

## 待办面板：排序、图标宽度、行数、卡死（本地补丁）

`tools/patch-pet-todo-ui.mjs`，在 tall 补丁之上继续改五处：

| 改动 | 为什么 |
| --- | --- |
| `sortTodos` / `sortTodoItems` 的 `a.createdAt - b.createdAt` → `b.createdAt - a.createdAt` | 没有截止时间的待办原来旧的在前，新加的直接沉底 |
| ✎/⏰/✕ 三个按钮内边距与最小宽度收窄，行内 `gap` `.462em` → `.3em` | 三个图标在原面板里占了近三分之一宽，正文被挤得只剩几个字 |
| `LIST_ROWS` 6 → 5 | 6 行时面板底部压到桌宠身上 |
| `AbortSignal.timeout(20000)` → `8000` | 保存请求卡住时禁用输入的时间太长 |
| `mutate` 改成 try/finally，忙碌时给出「正在保存上一条」提示 | 原来 `busy` 只有一条下降路径、且点击被静默吞掉，对话生成期间点待办像「点了没反应」 |

**排序那条改在宿主**（`lib/index.js` 的 `sortTodos`）：`/todos` 返回的顺序就是两端显示的顺序，网页端 bundle 里根本没有排序函数（被 tree-shake 掉了）。所以这条要等 DSH 重新加载插件或重启 DSH 才生效，只重启桌宠窗口不够；其余四条只改客户端，`POST /dsh-pet-7340/reload` 加刷新页面即可。

```bash
node tools/patch-pet-todo-ui.mjs            # 打补丁（幂等）
node tools/patch-pet-todo-ui.mjs --check    # 只看状态
node tools/patch-pet-todo-ui.mjs --restore  # 用 .pre-todoui.orig 还原
```

标记 `/* dsh-pet-todo-ui v1 */`、备份后缀 `.pre-todoui.orig`。每个文件要求改动集合完全命中（宿主只要排序一条，桌面端 `shared-core.js` 要全部五条，网页端 `client.js` 要除排序外的四条），任何一处锚点缺失或重复都整体放弃、不写文件。
